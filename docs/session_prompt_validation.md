## 1. Цель и границы

Подтвердить, насколько возможно **без разведённой PCB**, что схема `01_control` электрически корректна и соберётся без ошибок. PCB `01_control` пока **не разведена**, поэтому доступны только схемотехнические и BOM-проверки (слои 1–5 ниже). Платные проверки (DRC/PDN/SI/термо/EMC/DFM) — **ОТЛОЖЕНЫ** до разводки.

### Честно о том, что даёт и не даёт каждый слой

- **ERC** ловит только связность (КЗ, висящие пины, типы пинов), **НЕ** правильность номиналов (100 кОм вместо 10 кОм ERC не увидит).
- **Review правил** — детерминированные правила встраиваемых плат (развязка, reset, I2C pull-up, питание, семейство MCU).
- **Contract-проверка** — совпадение пинов символа↔футпринта (иначе физически не соберётся).
- **Derating** — запас по напряжению/току/мощности (компонент не пробьёт/не сгорит).
- **SPICE** — математика дискретных узлов, качество = качество моделей.
- **Никакой инструмент не заменяет физический bring-up** (мультиметр/осциллограф: поднятие питания, кварц, загрузка прошивки, уровни сигналов).

## 3. Порядок проверок (слои 1–5)

### Слой 1 — ERC и связность (KiCad MCP)

1. `kicad_set_project` → активен `01_control`.
2. `run_erc(save_report=true)` → зафиксировать число violations (error/warning) и полный список.
3. `sch_check_power_flags` → убедиться, что силовые шины движимы/помечены:
   `+5V`, `+3V3`, `+3V3_SI`, `+3V3_DISP`, `+12V_PA`, `+12V_RXTX`, `GND`.
4. `sch_get_connectivity_graph` → общая связность; для критичных цепей прогнать `sch_trace_net`:
   `+3V3_DISP`, `VFO`, `BFO`, `I`, `Q`, `PTT`, `MIC_LINE`, `MUTE`, `RX_audio`,
   `+12V_PA`, `+12V_RXTX`, `PWR_LIMIT_EN`, `PWR_LIMIT_SW`, `I_sense`, `SWR_sense`,
   `IQ_EN`, `SPI_SCK`, `SPI_MOSI`, `SPI_CS`, `SPI_DC`, `OLED_*`, `LCD_RST`, `LCD_BLK`.
5. `sch_get_symbols` → проверить уникальность refdes (нет дублей).

### Слой 2 — Детерминированные правила встраиваемых плат (embedcalc)

6. `embedcalc_list_schematic_rules(family="stm32f4")` → каталог правил (для понимания).
7. `export_netlist` (KiCad MCP) → найти получившийся `.net` файл (обычно в `KiCad/01_control/` или его `output/`).
8. `embedcalc_parse_kicad(path=<абсолютный путь к .net>)` → получить standard schema.
9. Добавить в schema `"mcu": {"family": "stm32f4"}` и вызвать
   `embedcalc_review_schematic(schematic=<schema с mcu.family>)`.
10. Зафиксировать `violations[]`, `checked[]`, `skipped[]`.
    **Важно:** `skipped` = правила, которые не удалось прогнать — читать обязательно;
    «чистый» результат покрывает только то, что в `checked`.

### Слой 3 — Контракт символа↔футпринта↔пина (локально, без сети)

11. `lib_verify_component_contract(reference=...)` для каждого IC и ключевых компонентов:
    `U1`, `U2`, `U3`, `U4`, `U5`, `U6`, `U7`, `U8`, `U9`, плюс электролиты `C1`/`C3`,
    ферриты `L2`/`L3`, клеммники и XH-разъёмы.
12. Зафиксировать статус `PASS/WARN/FAIL` и `findings` по каждому.

### Слой 4 — Номиналы и derating (сверка BOM + расчёт)

13. `lib_check_derating(...)` по конденсаторам (parameter=`voltage`, запас ≥ 20%) и резисторам
    (parameter=`power`). Рабочие значения сверять с `docs/bom/stage1_control.md` и схемой.
14. Точечно пересчитать ключевые узлы калькуляторами `embedcalc_*`:
    - `embedcalc_crystal_load_caps` для Y1 (8 МГц) и Y2 (27.6 МГц) → корректность C9/C10/C18/C19.
    - `embedcalc_rc_filter` для RC-фильтров UI (R=10к, C=100нФ → τ≈1 мс) и `RX_audio` RC.
    - `embedcalc_op_amp` для MIC-предусилителя U7 (неинвертирующий, усиление ≈10).
    - `embedcalc_i2c_timing` для I2C pull-up R3/R4 (4.7 кОм) при необходимости.
15. (Опционально, если есть сеть) `lib_check_stock_availability(refs=[...])` — наличие позиций BOM.

### Слой 5 — SPICE дискретных узлов (опционально, по наличию моделей)

16. Моделировать только то, что имеет модель: **MIC-предусилитель (LM358)**, **RC-фильтры**.
    - `create_model(component_type="opamp", name="LM358", ...)` или `list_models`.
    - `create_circuit` / `load_template` + `run_ac_analysis` / `run_transient` / `run_dc_op`.
    - `compare_specs` / `measure_bandwidth` / `measure_gain` для проверки спецификаций.
    - **Ограничение:** у Si5351 / 74HC74 / STM32 поведенческих моделей «из коробки» нет —
      целиком схему не моделировать.

## 4. Отчёт (deliverable)

Создать **`docs/session_report_validation.md`**:

1. Сводка: PASS/WARN/FAIL по каждому слою.
2. ERC: итоговое число error/warning + список.
3. Review `stm32f4`: violations / checked / skipped.
4. Contract-проверка: таблица `ref → статус → finding`.
5. Derating: таблица `компонент → параметр → рабочее/номинал → запас → verdict`.
6. Расчёты `embedcalc_*`: значение из BOM vs расчётное → вывод.
7. SPICE (если был): что смоделировано + результат.
8. **Список найденных проблем** по критичности, с рекомендацией, **БЕЗ автоисправления**.
9. **Что осталось не покрыто** (skipped / ограничения) — честно.

## 6. Что НЕ делать

- **Не править схему** `01_control.kicad_sch` — это read-only сессия.
- Не трогать `00_master`, `sym-lib-table`/`fp-lib-table`.
- Не запускать `sch_annotate`.
- Не разводить PCB (`01_control.kicad_pcb`).
- Не травить/монтировать плату.
- Не «чинить» найденные ошибки молча — только фиксировать в отчёте и сообщать.
- Не параллелить KiCad MCP-вызовы; перечитывать файл после каждой операции.
- Коммитить (если понадобится закоммитить отчёт) — **только после явного согласия пользователя**.
