# ТЗ для KiCad-сессии: схемотехника `02_power_amp` (этап 2, подэтапы 2.1–2.3)

> **Для кого:** отдельная сессия агента с доступом к KiCad MCP.
> **Источник правды по составу:** [`docs/bom/stage2_power_amp.md`](../bom/stage2_power_amp.md).
> **Контракты (источник правды по интерфейсам):** [`docs/contracts/control_pa.md`](../contracts/control_pa.md) и [`docs/contracts/rxtx_pa.md`](../contracts/rxtx_pa.md).
> **Проектные расчёты:** [`docs/calculations/pa_stage2.md`](../calculations/pa_stage2.md), [`docs/calculations/lpf_27mhz.md`](../calculations/lpf_27mhz.md).
> **Состав проекта сейчас:** `02_power_amp` — заготовка (пустая схема). Контракты `control_pa.md` / `rxtx_pa.md` — **ЗАФИКСИРОВАНЫ**.

> **Правило:** правки `.kicad_sch` / `.kicad_pro` — ТОЛЬКО через MCP-инструменты KiCad. Не редактировать S-выражения текстом.
> **Правило (символы/компоненты):** если при вставке символа/компонента возникает проблема резолва/видимости библиотеки — **НЕ решать самостоятельно** (не править `sym-lib-table`/`fp-lib-table`, не генерировать дубликаты). Остановиться и сообщить пользователю, какой именно символ/компонент нужен (refdes, library, symbol_name, value, footprint, координаты).

## 0. Подготовка

1. Проверить наличие `KiCad/02_power_amp/02_power_amp.kicad_pro` и `02_power_amp.kicad_sch`.
2. Открыть проект и файл схемы через MCP (`kicad_set_project` с `project_dir` + `sch_file`).
3. **Убедиться, что активен именно `02_power_amp`** (не `00_master`, не `01_control`, не `03_rx_tx`).
4. Работать последовательно: одна операция → проверка → следующая. Не запускать параллельные KiCad-вызовы.
5. Лист A3 (или A4 при нехватке места) — как в `01_control`.

**Библиотеки:** стандартные KiCad (`Device`, `Package_TO_SOT_SMD`, `Connector`, `Connector_JST`, `Connector_Coaxial`, `Capacitor_SMD`, `Inductor_SMD`, `Transformer`, `Relay`, `Switch`, `Potentiometer_THT`, `Diode_SMD`, `Amplifier_Operational`, `Transistor_FET`) + кастомная `trx_custom`.

| Компонент | Символ | Footprint | Примечание |
|-----------|--------|-----------|------------|
| RD16HHF1 (Q1, Q2) | `trx_custom:RD16HHF1` ⚠️ | `Package_TO_SOT_SMD:TO-220-3_Vertical` (штатный) | MOSFET. **Цоколёвка НЕСТАНДАРТНАЯ: 1=GATE, 2=SOURCE, 3=DRAIN, 4=FIN(SOURCE)** (2=Source, 3=Drain, фланец=Source). | Трансформаторы T1/T2/T_swr | `Transformer:*` (ближайший) или custom ⚠️ | пады/тора (custom `.kicad_mod`) ⚠️ | бифилярные на BN-43-202/FT-37-43. Допустимо изобразить как блок с 4–6 выводами + подписи намоток. |
| Реле K1 | `Relay:Relay_DPDT` | по факту выбранного реле ⚠️ | цоколёвка по даташиту реле |
| Тумблер SW1 | `Switch:SW_SPDT` / `SW_DPDT` | **на корпус (панель)**; на плате — пады/разъём XH2.54 ⚠️ | LIMIT/FULL |

> ⚠️ Если MCP не может создать/резолвить `RD16HHF1` или трансформаторы — остановиться и запросить ручную правку в GUI (по правилу). Не подменять на произвольный символ молча.

> ⚠️ **Символ RD16HHF1 (важно):** нумерация пинов символа должна соответствовать цоколёвке **1=GATE, 2=SOURCE, 3=DRAIN, 4=FIN(SOURCE)** (вывод 2 = Source, вывод 3 = Drain, фланец = Source). Footprint `TO-220-3_Vertical` универсален; маппинг пинов задаётся ТОЛЬКО в символе. Source = вывод 2 + фланец (FIN).

## 2. Подэтап 2.1 — Push-pull УМ (RD16HHF1 + трансформаторы)

### Цепи
```
J_RF_TX (SMA, вход TX_RF ~0.5 Вт, 50 Ом)
   → T1 (входной балун, 50 Ом → балансные затворы)
   → R_g1/R_g2 (4.7–10 Ом, 0603) → затворы Q1/Q2
Q1/Q2 (RD16HHF1): истоки → GND_PWR (общий), стоки → T2 (выходной балун)
T2: центр первички → L_rfc → +12V_PA
    вторичка → выход 50 Ом (на ФНЧ 2.2)
```

| Ref | Действие |
|-----|----------|
| Q1, Q2 | RD16HHF1, push-pull, истоки на GND (фланец=Source), стоки на первичку T2 |
| T1 | входной балун (BN-43-202), бифиляр, коэффициент — место под 1:1 / 4:1 |
| T2 | выходной балун (BN-43-202 / BN-61-202), центр первички = питание |
| L_rfc | дроссель стока, 4–6 мкГн (FT-50-43 / T68-2) |
| R_g1, R_g2 | затворные 4.7–10 Ом (антипаразитные) |
| R_fb1, R_fb2 | (опц.) ОС 100–220 Ом, место зарезервировать |
| C_rf_d | 100 нФ развязка стоков ×2 |
| C_bulk_pa | 470 мкФ/25 В SMD (`CP_Elec_10x10.5`, уточнить по факту детали) |
| C_pa_byp | 10 мкФ (0805) + 100 нФ развязка +12V_PA |

> **Активный драйвер — НЕ ставим в базовой версии**, но зарезервировать место/пады (после измерения усиления на макете).

## 4. Подэтап 2.3 — Датчики + LIMIT/FULL + смещение + T/R (БЛОКИРУЮЩИЙ)

> Разводится **совместно с 1.5** (контракт `control_pa.md` уже зафиксирован). До завершения 2.3 плату этапа 1 не травить.

### 4.1 Разъёмы интерфейса (по контракту `control_pa.md`)
| Разъём | Пин | Сигнал |
|--------|-----|--------|
| J_PA_CTRL_1 (XH2.54 6P) | 1 | GND |
| | 2 | PTT |
| | 3 | PWR_LIMIT_EN |
| | 4 | PWR_LIMIT_SW |
| | 5 | I_sense |
| | 6 | SWR_sense |
| J_PA_PWR_1 (клеммник 2P 5.0 мм) | 1 | +12V_PA |
| | 2 | GND |

### 4.2 Смещение + LIMIT/FULL
```
+12V_PA → делитель Vgg (с опц. NTC/диодом) → SW1 (полюс A):
   LIMIT → RV1 (подстроечник) → узел Vgg → R_g1/R_g2 → затворы
   FULL  → полный Vgg → узел Vgg → затворы
PWR_LIMIT_EN (3.3 В, active-high) → Q_lim (2N7002) → принудительно RV1 (LIMIT)
LED D_lim + R_led → горит при (LIMIT ИЛИ PWR_LIMIT_EN)
PWR_LIMIT_SW ← делитель 27к/10к от +12 В, переключается SW1 (полюс B): LIMIT=3.3 В, FULL=0 В
```

| Ref | Действие |
|-----|----------|
| SW1 | DPDT: полюс A = смещение (RV1 vs полный Vgg), полюс B = PWR_LIMIT_SW |
| RV1 | подстроечник 3296W 10к (калибровка 4 Вт) |
| D_lim + R_led | светодиод LIMIT + резистор 1–2.2 к |
| Q_lim | 2N7002, ключ PWR_LIMIT_EN |
| R_lim_pu/pd | 27к / 10к делитель PWR_LIMIT_SW |

### 4.3 T/R реле
```
PTT (3.3 В) → Q_ptt (2N7002/MMBT3904) → катушка K1 (12 В) + D_rel (1N4148WS, обратный)
K1: COM → J_ANT (антенна)
    NO (TX) → выход ФНЧ
    NC (RX) → J_RF_RX (на 03_rx_tx)
```

| Ref | Действие |
|-----|----------|
| K1 | реле DPDT 12 В (одна группа или обе — по схеме T/R) |
| Q_ptt | ключ реле |
| D_rel | обратный диод 1N4148WS (SOD-323) |

### 4.4 Датчики
| Ref | Действие |
|-----|----------|
| R_shunt | 0.05 Ом / ≥3 Вт в шине +12V_PA → U_sense (LM358, single 12 В) → I_sense (0–3.3 В) |
| U_sense | LM358, усиление ~22, выход делитель/ограничение ≤3.3 В |
| T_swr | трансформатор тока FT-37-43 (мост Стоктона) на линии J_ANT |
| D_swr | BAT54 ×2, детектор → SWR_sense (0–3.3 В) |

## 6. Критерии готовности (Definition of Done)

- [ ] ERC: нет **новых** `pin_to_pin` / `multiple_net_names` / `power_pin_not_driven`. Допустимы `Pin not connected` у NC и (до стыковки с этапом 3) изолированные `TX_RF`/`RX_RF`.

- [ ] Отчёт: таблица «ref → что сделано → отклонения», список выбранных футпринтов/символов, остаточные ERC.
